# M4z — β 를 구간·판 단위로 섞는 수집 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** M4w·M4x 에서 새 손실(회피 가중) 학생이 모은 데이터는 첫 라운드부터 해로웠다. 가설은 수집에서 β 섞기가 **걸음마다**(0.1 초마다 동전) 일어나, 학생이 다르게 움직일수록 선생님 계획기(상태를 기억하는 차로변경 로직)가 흔들리고 라벨이 일관되지 않다는 것이다. 섞는 단위를 **구간(여러 걸음)·판 전체**로 바꿀 수 있게 하고, 새 손실 학생으로 DAgger 를 다시 돌려 데이터가 좋아지는지 잰다.

**Architecture:** `vtd_rl/policy/collect.py` 에 누가 몰지를 정하는 작은 클래스 `DriverSchedule` 를 두고, `collect_episode(..., mix="step", mix_len=30)` 가 그것을 쓴다. 기본값 `"step"` 은 지금 코드와 **같은 난수 소비**로 비트 동일하다. `scripts/run_dagger.py` 에 `--mix {step,segment,episode}`·`--mix-len` 을 넣어 작업 묶음으로 일꾼에게 넘긴다.

**Tech Stack:** Python 3.10, numpy 1.26.4, pytest. 본 실행은 OMEN.

**Spec:** 이 문서. 직전 증거 `docs/reports/m4x-round-data.md`·`docs/reports/m4y-best-data.md`.

## 실험 설계 (본 실행 — 계획 주관자, 구현 과제 아님)

- 손실은 M4y 승자 그대로: 앵커 2 · `near_m` 30 · `near_weight` 3.
- 섞기 셋: `step`(대조군, 지금과 같다) · `segment`(`--mix-len 30` = 30 걸음 ≈ 3 초) · `episode`(판 전체).
- 각각 `run_dagger --rounds 3 --betas 1.0,0.5,0.5 --stage stage3b --variants 4 --eval-stage stage1 --eval-stage stage3b --select last --train-seed S`, 학습 시드 0~4. 라운드 0~2 데이터(D2)를 만든다.
- 데이터 품질 잣대: 각 실행의 D2 로 `refit_round.py --upto 2 --anchor-coef 2 --near-m 30 --near-weight 3 --batch-seed {100+S} --ema-halflife 2500` EMA 그물을 학습하고 선택 창 v8~v11 로 잰다. **기준은 M4y 의 같은 명령(M4s D2): 73.6 · 69.4 · 62.5 · 69.4 · 79.2, 평균 70.8%** 다.

### 판정 기준 (미리 적는다)

`E_mode` = 그 섞기로 모은 D2 의 EMA2500 ③b(선택 창) 데이터 시드 5 개 평균.

- 섞기 하나가 **좋은 데이터를 모은다** = `E_mode ≥ 66.8%`(기준 70.8 − 4) **그리고** ① 평균 ≥ 90%.
- **가설이 맞다** = `step` 은 좋은 데이터를 못 모으고(`E_step < 66.8`) `segment`·`episode` 중 하나 이상이 모은다.
- **가설이 틀렸다** = 셋 다 못 모은다 — 섞는 단위가 아니라 새 손실 학생이 만드는 상태 자체가 문제다.
- `step` 도 모은다면 — 손실 설정(앵커 2·가중 3)이 M4w(앵커 3·가중 4)와 달라서 생긴 차이일 수 있다고 적고 판정을 내리지 않는다.

```python
#: β 를 섞는 단위. "step" 은 걸음마다(예전 그대로), "segment" 는 `mix_len` 걸음마다 한 번,
#: "episode" 는 판마다 한 번 동전을 던진다(M4z).
MIX_MODES = ("step", "segment", "episode")


class DriverSchedule:
    """걸음마다 **누가 모나**(학생이면 True)를 정한다 — 난수는 필요할 때만 뽑는다.

    ★ "step" 은 예전 `rng.random() >= beta` 를 걸음마다 한 번 부르는 것과 **같은 난수 흐름**이다.
    그래야 같은 시드로 지난 실행의 조각을 재현한다. 정책이 없으면(선생님만) 난수를 아예 안
    쓴다 — 예전에도 `policy is not None and ...` 이라 안 썼다.

    "segment" 는 `step % mix_len == 0` 인 걸음에서만 새로 뽑고 그 구간 내내 같은 운전자를 쓴다.
    "episode" 는 첫 걸음에서 한 번 뽑는다. M4w·M4x 가설: 걸음마다 섞으면 학생이 다르게 움직일
    때 선생님 계획기(차로변경 결정 같은 상태)가 자기 계획대로 차가 안 움직이는 걸 겪고, 그
    상태의 라벨이 흔들린다.
    """

    def __init__(self, beta, mix, mix_len, rng, has_policy):
        if mix not in MIX_MODES:
            raise ValueError(f"모르는 mix {mix!r} — {MIX_MODES} 중 하나")
        if int(mix_len) < 1:
            raise ValueError(f"mix_len 은 1 이상이어야 한다(mix={mix!r}) — {mix_len!r}")
        self.beta, self.mix, self.mix_len = float(beta), mix, int(mix_len)
        self.rng, self.has_policy = rng, has_policy
        self.draws, self._on = 0, False

    def _draw(self) -> bool:
        self.draws += 1
        return self.rng.random() >= self.beta

    def student(self, step: int) -> bool:
        if not self.has_policy:
            return False
        if self.mix == "step":
            return self._draw()
        if self.mix == "segment":
            if step % self.mix_len == 0:
                self._on = self._draw()
            return self._on
        if step == 0:
            self._on = self._draw()
        return self._on
```
