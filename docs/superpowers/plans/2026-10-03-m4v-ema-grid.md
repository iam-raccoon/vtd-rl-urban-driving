# M4v — EMA 를 잣대로 앵커 계수 × 회피 가중 고르기 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** M4u 에서 EMA(반감기 2500 걸음)가 같은 데이터·같은 설정이면 배치 시드와 상관없이 거의 같은 그물(③b 표준편차 0.5 점)을 준다는 것이 나왔다. 이걸 잣대로 써서 **평균 실력(EMA ③b)을 올리는 학습 설정**을 학습 한 번씩으로 찾는다. 후보는 앵커 계수와 회피 표본 가중이다.

**Architecture:** `scripts/refit_round.py` 에 `--near-m`·`--near-weight` 를 넣어 `TrainConfig` 로 그대로 넘긴다(기본 0.0·1.0 = 지금과 비트 동일). 본 실행은 M4s 의 D4 데이터(시드 0~4) × 설정 격자를 EMA 를 켜고 한 번씩 학습하고, EMA 그물을 CPU 로 선택 창에서 잰다.

**Tech Stack:** Python 3.10, PyTorch, numpy 1.26.4, pytest. 본 실행은 OMEN.

**Spec:** 이 문서가 스펙이다. 직전 증거는 `docs/reports/m4u-ema.md`("다음" 1).

## 왜

- M4u: EMA 그물은 평균 ③b 약 16% 로 평범하고, raw 의 흔들림은 그 평균 주위의 궤적 끝 잡음이다. 선택은 위로 튄 꼬리를 고른다. **평균 자체를 올리면 분포 전체가 올라간다.**
- 앵커 계수: M4q 탐침에서 10 은 큰 행동 변화를 막았고, 0·1 은 단계 ① 을 무너뜨렸다. 3 만 DAgger 로 돌렸다. 2·5 는 안 봤다.
- 회피 가중(`near_m`·`near_weight`): 정지차 근처 표본은 데이터의 몇 % 뿐이라 손실을 평범한 주행이 지배한다(M4m). M4n 에서 가중을 시험했지만 그때는 계수 10 앵커가 변화를 막고 있었다. 계수 3 에서는 안 봤다.

## 실험 설계

**1 단계 — 격자(EMA 로 평균 실력 재기).** 데이터 D4(M4s 시드 `s` 의 라운드 0~4), 배치 시드 `100+s`(데이터 시드마다 하나), EMA 반감기 2500.

| 앵커 계수 \ 회피 가중 | 1(가중 없음) | 4 | 16 |
|---|---|---|---|
| 2 | a2-w1 | a2-w4 | a2-w16 |
| 3 | **a3-w1 = 기준점** | a3-w4 | a3-w16 |
| 5 | a5-w1 | a5-w4 | a5-w16 |

- `near_m` 은 30 m(M4n 과 같다). 가중 1 은 `near_m` 을 줘도 가중 없음 경로를 탄다(`train.py` 의 `near_weight == 1.0` 분기).
- 설정 9 × 데이터 시드 5 = **학습 45 개**, EMA 평가 45 개.
- 기준점 a3-w1 은 M4u 의 `B-s{s}-b{100+s}` 와 같은 명령이다. 다시 돌려서 원래 가중치가 M4t 의 `B-s{s}-b{100+s}/policy.pt` 와 같은지(`--compare`), EMA 숫자가 M4u 와 같은지 확인한다(재현 점검).
- 평가: 선택 창 v8~v11(③a·③b 각 72 판) + ① 원본 18 판, 평가 시드 3, CPU(`OMP_NUM_THREADS=1`). 보고 창은 안 쓴다.

**2 단계 — 승자 확인(1 단계에 승자가 있을 때만).** 승자 설정으로 데이터 시드 5 × 배치 시드 3(`s+4`, `100+s`, `200+s`) raw 그물 15 개를 선택 창으로 잰다. M4t 의 B(같은 데이터·기준 설정) raw 15 개와 성공 수를 비교한다.

### 판정 기준 (미리 적는다)

**1 단계.** 잣대 = EMA2500 ③b 완주율(선택 창)의 데이터 시드 5 개 평균. 기준점 = a3-w1.

- 설정 X 가 **평균을 올린다** = `mean(X) ≥ mean(기준) + 4.0 점` **그리고** 데이터 시드 5 개 중 **4 개 이상**에서 기준보다 높다 **그리고** X 의 ① 평균 ≥ 90%.
- 올리는 설정이 여럿이면 평균이 가장 높은 것이 **승자**다. 하나도 없으면 "이 격자 안에는 평균을 올리는 설정이 없다".

**2 단계.** 성공 = 선택 창 ③b ≥ 20%. 승자 raw 성공 수 `n_win` (15 개 중) vs M4t B 의 `n_B = 4`.

- **확인된다** = `n_win ≥ n_B + 4`(= 8 이상).
- 아니면 **EMA 평균 개선이 raw 성공으로 번지지 않았다**.

**재현 점검(관문):** a3-w1 다섯 개의 원래 가중치가 M4t `B-s{s}-b{100+s}/policy.pt` 와 같아야 한다. 하나라도 다르면 멈춘다.

# ── M4v: --near-m / --near-weight ────────────────────────────────────────────

def _obj_run(tmp_path, rounds=2, n=40, near_rows=20, fx_m=10.0):
    """조각마다 앞쪽 `near_rows` 행의 최근접 슬롯에 전방 `fx_m` m 물체를 둔 가짜 실행."""
    data = tmp_path / "objrun" / "data"
    for k in range(rounds):
        for i in range(2):
            sh = _shard(n, 100 * k + i)
            sh.objs[:near_rows, 0, 0] = fx_m / OBJ_X_M
            sh.mask[:near_rows, 0] = 1.0
            save_shard(sh, str(data / f"r{k}-course_X@v{i}-s0.npz"))
    return tmp_path / "objrun"


def test_near_기본값은_예전과_비트_동일(rr, tmp_path):
    run = _obj_run(tmp_path)
    init = _init_ckpt(tmp_path)
    base = ["--run", str(run), "--upto", "1", "--init", init, "--anchor-coef", "3",
            "--batch-seed", "2", "--epochs", "2", "--device", "cpu", "--no-eval"]
    assert _main(rr, base + ["--out", str(tmp_path / "plain")]) == 0
    assert _main(rr, base + ["--out", str(tmp_path / "explicit"), "--near-m", "0",
                             "--near-weight", "1",
                             "--compare", str(tmp_path / "plain" / "policy.pt")]) == 0
    row = json.loads((tmp_path / "explicit" / "row.json").read_text(encoding="utf-8"))
    assert row["compare"]["identical"] is True
    plain = json.loads((tmp_path / "plain" / "row.json").read_text(encoding="utf-8"))
    assert plain["near_m"] == 0.0 and plain["near_weight"] == 1.0
    assert {"train", "eval", "compare", "ema", "upto", "batch_seed"} <= set(plain)


def test_near_가중이_학습에_닿는다(rr, tmp_path):
    run = _obj_run(tmp_path)
    init = _init_ckpt(tmp_path)
    base = ["--run", str(run), "--upto", "1", "--init", init, "--anchor-coef", "3",
            "--batch-seed", "2", "--epochs", "2", "--device", "cpu", "--no-eval"]
    assert _main(rr, base + ["--out", str(tmp_path / "plain")]) == 0
    assert _main(rr, base + ["--out", str(tmp_path / "near"), "--near-m", "30",
                             "--near-weight", "16",
                             "--compare", str(tmp_path / "plain" / "policy.pt")]) == 0
    row = json.loads((tmp_path / "near" / "row.json").read_text(encoding="utf-8"))
    assert row["compare"]["identical"] is False
    assert row["near_m"] == 30.0 and row["near_weight"] == 16.0
    assert 0.3 < row["train"]["near_frac"] < 0.7          # 행의 절반에 10 m 물체


def test_물체가_없으면_near_frac_은_0(rr, tmp_path):

                      "--no-eval"]) == 0
    row = json.loads((out / "row.json").read_text(encoding="utf-8"))
    assert row["train"]["near_frac"] == 0.0


def test_refit_은_near_값을_TrainConfig_로_넘긴다(rr, tmp_path):
    run = _obj_run(tmp_path)
    init = _init_ckpt(tmp_path)
    net, train, _ = rr.refit(init, rr.load_upto(str(run / "data"), 1), upto=1, batch_seed=5,
                             epochs=2, max_updates=None, anchor_coef=3.0, init_seed=0,
                             dev="cpu", near_m=30.0, near_weight=4.0)
    ref = make_reference(rr.start_net(init, "cpu"))
    torch.manual_seed(0 + 1)
    want = rr.start_net(init, "cpu")
    tcfg = squash_aligned(TrainConfig(epochs=2, seed=5, anchor_coef=3.0, near_m=30.0,
                                      near_weight=4.0), want)
    want_train = train_epochs(want, rr.load_upto(str(run / "data"), 1), tcfg, device="cpu",
                              ref=ref)
    assert _same(_params(net), _params(want))
    assert train["near_frac"] == want_train["near_frac"] > 0.0


@pytest.mark.parametrize("bad", [["--near-m", "-1"], ["--near-weight", "0"],
                                 ["--near-weight", "-2"]])
def test_잘못된_near_값은_거부한다(rr, tmp_path, bad):
    run = _fake_run(tmp_path, rounds=2)
    init = _init_ckpt(tmp_path)
    with pytest.raises(SystemExit) as e:
        _main(rr, ["--run", str(run), "--upto", "1", "--init", init, "--anchor-coef", "0",
                   "--batch-seed", "0", "--out", str(tmp_path / "o"), "--device", "cpu",
                   "--no-eval"] + bad)
    assert e.value.code == 2
    assert not (tmp_path / "o").exists()


def test_dry_run_은_회피_가중을_보여준다(rr, tmp_path, capsys):
    run = _fake_run(tmp_path, rounds=2)
    init = _init_ckpt(tmp_path)
    assert _main(rr, ["--run", str(run), "--upto", "1", "--init", init, "--anchor-coef", "3",
                      "--batch-seed", "2", "--near-m", "30", "--near-weight", "4",
                      "--out", str(tmp_path / "o"), "--device", "cpu", "--dry-run"]) == 0
    text = capsys.readouterr().out
    assert "회피 가중" in text and "30" in text and "4" in text

2. **1 단계 학습 45 개**: `refit_round.py --run runs/omen/2026-10-02-m4s-s{s} --upto 4 --init runs/omen/2026-10-01-m4o-s0/policy-best.pt --anchor-coef {2|3|5} --near-m 30 --near-weight {1|4|16} --batch-seed {100+s} --ema-halflife 2500 --no-eval --out runs/omen/2026-10-03-m4v/a{A}-w{W}-s{s}`. a3-w1 은 `--compare runs/omen/2026-10-03-m4t/B-s{s}-b{100+s}/policy.pt` 를 단다. 학습은 메모리 관문(가용 7 GB·60 초 간격).
3. **EMA 평가 45 개**: `OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 eval_unseen.py --ckpt …/policy-ema2500.pt --device cpu --variants 4 --variant-offset 8 --stage stage1 --stage stage3a --stage stage3b --eval-seeds 3`, 24 갈래.
4. 판정 표(스크립트). a3-w1 의 EMA 숫자가 M4u 와 같은지 확인.
5. 승자가 있으면 **2 단계**: 승자 설정 × 데이터 시드 5 × 배치 시드 `s+4`·`100+s`·`200+s` raw 15 개(EMA 도 같이 저장), raw 를 같은 방식으로 평가. (`100+s` 는 1 단계 그물과 같은 학습이라 그 raw 만 새로 잰다.)
6. 성적표 `docs/reports/m4v-ema-grid.md`, README, 메모리, 푸시.
