# M6k — 중간 체크포인트까지 선택 창으로 고르니 최고 그물이 바뀌었다: 보고 창 ③ 전체 83.3%, ③a·③b 100%, ①② 100%

지금까지는 실행마다 `ac-best` 와 마지막 체크포인트만 안 쓴 판으로 쟀다. `ac-best` 는 PPO 가 학습 중 원본 판(단계마다 6 판 × 시드 1)으로 고른 것이다. M6k 는 두 번째 단계 실행 22 개(M6d~M6i)와 한 단계 실행 5 개(M6j)가 저장해 둔 중간 체크포인트 81 개를 **선택 창**으로 재고, M6h 의 고르기를 그 후보까지 넓혔다. 학습은 하지 않았다. 계획은 `docs/superpowers/plans/2026-10-04-m6k-ckpt-select.md` 다.

- 중간 체크포인트 81 개는 선택 창 ③ 전체만 쟀다(판 72 개씩, CPU, 동시 24, 약 11 분).
- 이미 잰 그물과 합친 후보는 122 개다. `ac-best`·마지막의 숫자가 같으면 하나로 셌다.
- 선택 창 ③ 전체 1 위만 아직 안 잰 단계(①·②·③a·③b 선택 창, 모든 단계 보고 창)를 마저 쟀다.
  - 계획은 상위 5 개를 마저 잰다고 했다. 4·5 위(84.7% 동점, 중간 체크포인트)는 재지 않았다.
  - 1 위가 지킴선을 통과해 고르기에 영향이 없기 때문이다(스크립트가 그것을 단언한다).

## 곁들여 — 실행 안에서 체크포인트를 바꾸면

- 실행 27 개에서 선택 창 ③ 전체의 (그 실행 최고 − `ac-best`)는 평균 +2.5 점, 최대 +12.5 점이다.
- 17 개 실행은 `ac-best` 가 이미 최고였다.
- 즉 `ac-best`(원본 판 6 개로 고름)도 대체로 괜찮은 체크포인트를 고른다. 다만 가끔 더 좋은 중간 체크포인트를 놓친다.

## 이 성적표가 주장하지 않는 것

- 고른 그물 하나의 보고 창 숫자다. 같은 학습을 다시 하면 같은 그물이 나온다는 주장이 아니다.
- 고른 그물은 M6g(③c 를 더한 칸)에서 나왔다. 그래서 ③c 가 좋다는 뜻은 아니다. M6g 칸 평균은 "차이 없다" 였다.
